# 中式美学 AI 视频风格库 · dsh-vidstyle

本库把「某种视觉风格」翻译成**能直接粘进视频模型的中文提示词**。12 个风格，6 个国风原创 + 6 个国际重写，每个都是一份完整的方法卡（`STYLE.md`），外加两份公共技法（`LIB/`）。

**本库不生成图片或视频**，只产出提示词。生成交给即梦 / Seedance / 可灵 / 万相。

---

## 1. 先判断：快查还是全流程

用户的话里能明确对上一个风格 → **走快查**（§2）。
用户只是想要一个风格化视频、没指定风格，或要跨多个镜头、要成片 → **走全流程**（§3）。

风格对照（中文关键词 → slug）：

|---|---|---|

## 2. 快查路径（用户已指定风格）

1. 读 `catalog.json` 找到 slug，打开 `styles/<slug>/STYLE.md`。
2. **只读 §10（提示词配方）**，把 `{主体}` `{环境}` `{运镜}` `{运动}` 按用户题材填掉。
3. 按 `LIB/PLATFORMS.md` §7 的默认假设（9:16 / 4 秒 / 即梦）出稿；用户指定了平台或画幅，按 §2、§4 换算。
4. 交付时给**一句话版**（快速试）+ **完整版**（正式跑）两条，并附一句该风格**最容易崩的点**（§9 的第一条）。

一句话版适合先跑一发试风格；完整版才用于正式生成。

---

## 3. 全流程路径（用户没指定风格，或要成片）

**第一步 · 定风格。**
读 `catalog.json`。按用户题材从 `traits` 里挑，给 2–3 个候选 + 各自的 `line`（一句话），让用户选。用户说不清时，按题材推荐：

- 传统文化 / 文物 / 节气 / 茶酒 → `dunhuang-feitian` `gongbi-flora` `song-minimal`
- 安静 / 高级感 / 产品静物 / 品牌调性 → `song-minimal` `ink-motion` `watercolor-bleed`
- 情绪 / 记忆 / 文艺 / 人文 → `ink-motion` `noir-archive` `collage-journal`
- 科技 / 汽车 / 数码 / 国潮联名 → `cyber-sino` `pixel-retro`
- 年轻 / 手作 / 生活方式 / 教程 → `collage-journal` `watercolor-bleed` `pixel-retro`
- 戏剧张力 / 人物 / 悬疑 → `noir-archive` `shadow-puppet`

**第二步 · 读全份方法卡。**
打开 `styles/<slug>/STYLE.md`，读 **§1–§9**（本质 / 材质 / 色彩 / 字体 / 运动 / 运镜 / 声音 / 招牌动作 / 避坑）。§1–§3 决定「像不像」，§6 §8 决定「怎么动」，§9 决定「怎么不崩」。

**第三步 · 写 treatment（一句话到一段）。**
用户要成片时，先用 3–5 句话定：主题、时长、画幅、几个镜头、用哪几个**招牌动作**（§8）。给用户确认后再往下。不要直接跳到逐镜提示词。

**第四步 · 逐镜出提示词。**
每个镜头按 §10 的完整配方填，运镜从 §6 表里**只选一个**，招牌动作从 §8 里取 1 个。镜头之间用 §6 的「允许的转场」衔接，不用禁止项。

**第五步 · 平台适配。**
按 `LIB/PLATFORMS.md` 换画幅（§2）、时长（§3）、语法（§4）、负面词（§6）。用户用图生视频时，按 §5 删掉风格锚点与材质段，加风格锁定句。

**第六步 · 排查（用户回来说不对时）。**
按 `LIB/TECHNIQUE.md` §8 的顺序查，**一次只改一个变量**：风格没进 → 提到句首；主体不对 → `{主体}` 加细节；颜色不对 → 保住 hex；动得不对 → 运镜运动拆两句；崩成 3D → 补 §9 专属负面词；没味道 → 加 §8 招牌动作。

---

## 4. 写提示词时的硬规矩

这几条违反了，效果会明显变差。来自 `LIB/TECHNIQUE.md`，写每一条提示词前都要守：

1. **风格锚点必须在句首。** 中文模型对开头响应最强。「这是一幅工笔绢本设色」放最前面。
2. **写材质，不写「感」。** 「很有水墨感」模型不执行；「生宣上洇开的湿墨，边缘有纤维毛刺」才执行。
3. **hex 色号保留不删。** 写具体色号，不要写「天青色」。
4. **运镜与运动拆成两个分句。** 合并写多数平台只执行一个。
5. **负面词放句末，单独一句**，且必须包含该风格 §9 的专属退化项（每个风格不一样，不要用通用模板）。
6. **占位符六类**：`{主体}` 由题材定（要具体到一个），其余五类从 `STYLE.md` 里取。

## 5. 文件地图

```
dsh-vidstyle/                        ← 插件包根（npm 包）
├─ package.json                       ← dsh.bundle manifest
├─ cordis.patch.yml                   ← profile roster 插入行
├─ index.js                           ← host 端入口，注册技能 provider
├─ lib/                               ← frontmatter 解析 + provider（零外部依赖）
├─ README.md
└─ skills/
   └─ dsh-vidstyle/                  ← 技能目录（resourceBase，相对路径从这里解析）
      ├─ SKILL.md                    ← 本文件，路由器
      ├─ catalog.json                ← 12 风格索引 + 默认参数（画幅/时长/平台/语序）
      ├─ LIB/
      │  ├─ TECHNIQUE.md             ← 提示词写法（原则/锚点/占位符/负面词/两层运动/排查）
      │  └─ PLATFORMS.md             ← 即梦/Seedance/可灵/万相对照（画幅/时长/语法/负面词）
      └─ styles/
         ├─ _template/STYLE.md       ← 11 节方法卡模板（新增风格照此写）
         └─ <slug>/STYLE.md          ← 12 份方法卡，节号固定
```

本文件里的相对路径（`catalog.json`、`LIB/…`、`styles/…`）都相对于 `skills/dsh-vidstyle/`，即技能的 `resourceBase`。

`STYLE.md` 的 11 节是固定契约，**别的指南会引用节号**，新增风格时不要改节序：

1 本质 · 2 材质 · 3 色彩 · 4 字体 · 5 运动 · 6 运镜 · 7 声音 · 8 招牌动作 · 9 AI 避坑 · 10 提示词配方 · 11 变化空间

**新增一个风格**：复制 `styles/_template/STYLE.md` 到 `styles/<slug>/`，11 节全部填满（§9 §10 是本库的核心，不能省），再往 `catalog.json` 的 `styles` 数组加一条（`slug` `cn` `en` `cat` `line` `traits` `native_moves` `file` 七字段齐全，`file` 必须能解析到真实路径）。

## 6. 边界

- **不生成图片或视频**，只产出提示词。
- **不写故事、不写分镜表、不做导演阐述**——那是用户或别的技能的事。本库管「一个镜头长什么样」。
- **不保证一次过。** 提示词提高命中率，不是确定性输出；§3 第六步的排查顺序为此存在。
- **`LIB/PLATFORMS.md` 的数值是结构性差异**（语序、负面词支持、图生视频行为），平台的时长上限与画幅选项会随版本变，用前以平台当前文档为准。
